# /update-packages - Read-Me additions

## Step 1: setup in the worktree

`npm ci` (its postinstall runs `scripts/patch-rn-jdk21.mjs`), then copy `android/local.properties`
from the primary checkout. Without it every Gradle check fails for reasons unrelated to the bump.

## Step 4: risks to show for a major (and for any bump marked below)

Check each against the package's own changelog before applying; this table says why the package
matters here, not what its next major changes.

| Package | Why it is risky here | Extra check |
|---|---|---|
| `@mozilla/readability`, `linkedom` | The text pipeline's `extract` (ADR 0006). A change in how a page parses corrupts the reading instead of crashing, and Hermes timing (F17: 1.5 s target, 5 s hard line) can move | `npm test` (the extract and devcheck-expected tests), then `npm run device:devcheck` on the phone: parity on every fixture and the F17 timings. It replaces the phone's build. Any bump, minor included |
| `react-native-safe-area-context` | A native module: its codegen `.so` is in the APK, and REA-38's reproducibility fix (`-ffile-prefix-map`) covers it | `build:release`, `fdroid-scan.sh`. Before the next release, `npm run repro` and `npm run fdroid:build` (an hour) |
| `typescript`, `eslint`, `jest`, `prettier`, `@types/jest` | They are the gates. A major can change what a gate checks | Diff the gate's output before and after (error counts, test counts). Never loosen `tsconfig.json`, `.eslintrc.js` or `jest.config.js` to get a bump through: those are gate-defining files |
| `license-checker-rseidelsohn` | The licenses gate does not use this devDependency: `scripts/check-licenses.mjs` runs its own pinned `npx -y license-checker-rseidelsohn@5.0.1`. Bumping only the devDependency changes nothing the gate checks | Say so in the PR. Moving the gate to a new version is a change to `scripts/check-licenses.mjs`, a gate-defining file, and goes through `/ship` with a critic, not through this command |
| `@types/node` | `engines.node` is `>= 22.11.0`, and the F-Droid recipe builds with Debian forky's Node. A newer `@types/node` major can type APIs that Node lacks | Keep its major at or below the Node major the recipe uses; check the recipe before applying |
| `@babel/*` | Metro and Jest transform every source file through them | `npm test`, `build:release` |

Any new dependency, or a bump that adds transitive packages, is non-negotiable 14 territory: every
package OSI-licensed (CC-BY-4.0 data-only exceptions only under ADR 0002), no Play Services,
Firebase or proprietary SDK. `licenses` and `fdroid-scan.sh` grade it, and a failure there is a
BLOCK: revert and hold the package. A new runtime dependency that reaches the network from JS
breaks non-negotiable 6; `npm test` includes `networkGuard.test.ts`.

## Step 5: after each commit

`android/app/src/main/assets/notices.json` is regenerated by `npm run notices` and is part of the
commit whenever it changes; `build:release` refuses a stale one. Explain any change in the commit
body (which packages entered, left or changed version in Settings > Licenses).

## Step 6: the PR body

Add the phone line. None of the gates exercise the app on the reference device:
`NOT VERIFIED ON DEVICE` unless `npm run device:smoke` ran on the branch's build (it takes
`.claude/device.lock/`; never wait for it, never a data-wiping install), and for the text-pipeline
packages above, `device:devcheck`.
